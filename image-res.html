Image Resolution Test Summary

Scope

We compared the current 720w image against the newer 1440w image for the same asset family and measured image request time in Chrome DevTools Network.

We also checked the LCP breakdown and confirmed that this image is the LCP element on the tested page.

Data Sources

  • Network timings captured for:
    • unthrottled
    • Slow 4G
    • 3G
  • LCP breakdown from DevTools Performance
  • Raw timing samples stored in:
    • network_image_times_720_vs_1440.csv

LCP Breakdown Observed

From the DevTools LCP breakdown for the tested page:

  • Time to first byte: 2780 ms
  • Resource load delay: 70 ms
  • Resource load duration: 160 ms
  • Element render delay: 500 ms

The image is the LCP element, but the biggest contributor to total LCP in this trace is server response time, followed by render delay after the image is available.

Interpretation

Unthrottled

On a fast connection, the move from 720w to 1440w adds about 32 ms on average. That is measurable but relatively small in the context of a multi-second LCP.

Slow 4G and 3G

On constrained networks, the larger image has a much larger impact:

  • Slow 4G adds about 2.0 s
  • 3G adds about 7.4 s

This means the higher-resolution image is much more likely to materially worsen LCP for users on slower networks, especially because this image is the LCP element.

Main Conclusion

The 1440w image does have potential LCP impact.

  • On fast connections, the impact appears modest.
  • On Slow 4G and 3G, the impact is significant and likely user-visible.
  • In the current trace, overall LCP is still dominated by backend TTFB, so image optimization is not the largest performance opportunity.

Recommendation

Use the 1440w image only when there is a clear visual quality requirement that justifies the cost.

If we keep the higher-resolution asset, we should also:

  • verify the rendered slot size and avoid overserving bytes
  • confirm the browser is not selecting 1440w for cases where 720w is visually sufficient
  • prioritize improving TTFB, since that is the largest current LCP contributor
  • investigate the 500 ms render delay after image load

Suggested Team Takeaway

Increasing this LCP image from 720w to 1440w causes a small regression on fast connections but a very large regression on Slow 4G and 3G. Since this image is the LCP element, the change can meaningfully worsen user experience on slower networks. The current page's biggest LCP bottleneck is still TTFB, so backend improvements should remain the top priority.
